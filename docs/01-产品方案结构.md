# 01 · 产品方案结构

> 文档版本：v0.1（首版）｜ 日期：2025-08-22 ｜ 状态：待评审
> 产品工作名：**双城记**（正式名待定）

---

## 1. 项目背景与愿景

### 1.1 背景

- 深圳/杭州聚集了大量互联网、科技、AI 从业者，具备**技能富余**与**旅居向往**；
- 昆明/大理是年轻人心中的旅居目的地，本地有大量**在地生活供给**（带玩、攻略、吃喝、在地圈子）与**AI 学习需求**；
- 现有旅游平台解决的是「交易」，但没有解决「人与人交换」与「交朋友」的问题；
- 文旅与 AI 是两个正在交叉的热点，中间缺少一个轻量的社区化连接器。

### 1.2 愿景

> 做一个「深圳教 AI、云南带玩」的双向交换社区，让技能与风景互换，让两座城市的人互相成为对方城市的「本地朋友」。

### 1.3 产品本质

**兴趣社区 + 技能交换 + 文旅推荐** 的混合体，未来可演变为：

- AI 技能课程（深圳侧教学变现）
- 本地体验产品（云南侧带玩变现）
- 企业游学 / 团建（To B 场景）
- 会员制社群
- 旅居陪玩撮合（双边撮合抽佣/会员费）

## 2. 产品定位

### 2.1 一句话定位

> 用技能换风景，用交换交朋友 —— 深圳/杭州 × 昆明/大理的 AI 技能交换与旅居交友社区。

### 2.2 定位主线（v1）

**双线并重**：

| 入口 | 路径 | 适用用户 |
| --- | --- | --- |
| 🗣️ **先认识**（社区线） | 浏览资料卡 → 发现有趣的人 → 加社群/报名 → 组局 | 想交朋友、慢热、先看人 |
| 🔗 **先匹配**（撮合线） | 发需求 → 系统按标签匹配 → 看到推荐的人 → 报名/约局 | 目标明确、要效率 |

> 首页两个 CTA 并行：**「先逛逛，认识人」** 与 **「发个需求，找对人」**。

### 2.3 产品形态

- **第一版**：PC 官网（轻社群官网展示 + 带产品的二级页）
- 风格：年轻社交产品感 + 文旅风格（山野、洱海、城市天际线视觉元素）
- 二级菜单页带真实产品能力：**匹配 / 报名 / 私信（二期）**

### 2.4 竞品参照（不是对手，是对标参考）

| 参照 | 借鉴点 |
| --- | --- |
| 豆瓣小组 / 城市兴趣组 | 兴趣为核、轻运营的社区感 |
| 技能交换平台（如 Skillshare 线下版） | 等价交换的心理机制 |
| Soul / 即刻 | 年轻人社交产品感、资料卡 |
| Airbnb Experiences | 本地人带玩的体验化呈现 |
| 小红书 | 文旅内容种草调性 |

## 3. 目标用户

### 3.1 用户分层

#### 深圳/杭州侧（供给 AI 技能 · 需求旅居体验）

- **核心人群**：互联网 / 科技 / AI 从业者为主，22–38 岁
- 特征：工作 1 年以上，薪资中上，有假期旅居意愿；愿意花 1 小时教 AI、做资源对接、职业交流
- 动机：去云南有人带、少踩坑；旅居期间有人陪；交到真实朋友；顺带做点利他的事
- 反例用户：只想要低价跟团游、无交换意愿的人（暂不服务）

#### 昆明/大理侧（供给带玩 · 需求 AI 技能）

- **核心人群**：本地年轻人、新大理人/新昆明人、文旅/民宿/咖啡/手作从业者，20–35 岁
- 特征：熟悉本地玩法，有时间，有内容产出能力（拍照、探店、路线）；想学 AI 提效（自媒体、民宿运营、接单）
- 动机：学 AI 技能、认识一线朋友、给自己的店/作品带来流量、顺带赚带玩服务费
- 反例用户：纯游客中介、无交换诚意者

#### 杭州侧（第三城）

- 作为供给池补充（杭州互联网从业者多，且去云南同样热门），v1 在文案与表单中预留城市选项，不单独做运营重点。

### 3.2 用户画像卡（Persona）

**深圳侧 · 阿哲（28 岁，AI 产品经理）**
- 想 11 月去大理旅居两周，怕踩坑、想有人带；
- 能教：AI 工具入门、提示词、产品思维；
- 想要：本地朋友、真实路线、摄影搭子。

**大理侧 · 阿花（26 岁，民宿主理人 + 咖啡师）**
- 大理生活 3 年，会带人骑车环洱海、找小众咖啡馆；
- 想学：用 AI 做小红书文案、民宿智能客服；
- 想要：一线城市的朋友、客源、技能。

**深圳侧 · 小林（31 岁，后端工程师）**
- 周末闲、想远程社交；能讲 AI 应用开发；
- 不一定要去云南，先线上认识，后续再组局。

## 4. 核心场景与用户故事

### 4.1 三大核心场景（一级菜单 → 二级菜单）

| 一级菜单 | 二级菜单 | 场景说明 |
| --- | --- | --- |
| 🏞️ 玩法 / 加入 | **A. 深圳人想去云南有人带** | 深圳侧发旅居/游玩意向，匹配云南本地带玩者 |
| | **B. 云南本地人想学 AI** | 云南侧发学习需求，匹配深圳侧 AI 教学者 |
| | **C. 双方交朋友、建圈子** | 资料卡浏览、社群加入、组局报名 |

### 4.2 用户故事（按优先级）

**P0（v1 必须支持）**
1. 深圳侧用户浏览官网 → 了解玩法 → 填写报名表（意向城市/时间/想交换什么）→ 进微信群；
2. 云南侧用户浏览官网 → 了解玩法 → 填写报名表（能带什么/想学什么）→ 进微信群；
3. 用户在「找人」页看到公开资料卡，按标签筛选（城市/技能/爱好/交友目的）；
4. 用户在「发需求」页提交需求，系统按标签匹配推荐人；
5. 用户看到付费带玩服务（带玩/陪游/摄影/包车）的展示与报名入口（线下结算）。

**P1（二期）**
6. 站内私信沟通；
7. 活动/组局报名（线下见面局、AI 公开课、旅居团）；
8. 社群运营后台（群内机器人、报名汇总）。

## 5. 交换机制设计

### 5.1 「深圳教 AI，云南带玩」交换形式（v1 支持）

| 形式 | 说明 | 典型场景 |
| --- | --- | --- |
| **A. 一对一互换** | 1 个深圳人 ↔ 1 个云南人 | 1 小时 AI 教学换半天陪玩 |
| **B. 一对多** | 1 个深圳人教 N 个云南人 | AI 入门小课（3–5 人） |
| **C. 小团对小团** | 深圳小团 ↔ 云南小团 | 深圳 4 人团 × 大理 2 个本地带玩者 |
| **D. 自由组局（默认原则）** | 平台不强制配对，社群内自由聊 | 群里喊一声就组局 |

> 产品设计原则：**先自由组局，不强制** —— 所有结构化匹配只是「推荐」，最终约局由用户自己决定。

### 5.2 交换内容标准化建议

**深圳侧（教学/资源方）**
- 1 小时 AI 入门课（工具介绍、提示词、实操）
- 一次资源对接（人脉/工具/行业信息）
- 一次职业交流（简历、方向、行业视野）

**云南侧（带玩/在地方）**
- 半天陪玩（本地路线、私藏点位）
- 接站 / 送站
- 带吃喝（地道小店、咖啡馆）
- 带逛本地景点（含讲解）

> 同时支持**自由无标准交换**：用户可自定「我能给 / 我想要」的自由文本，不强制套模板。

### 5.3 付费旅居服务（v1 开放）

| 服务 | 说明 | v1 处理 |
| --- | --- | --- |
| 带玩服务费 | 本地人收服务费带玩 | ✅ 开放，线下结算 |
| 陪游费 | 全程陪游 | ✅ 开放，线下结算 |
| 摄影费 | 旅拍跟拍 | ✅ 开放，线下结算 |
| 包车费 | 本地车辆带游 | ✅ 开放，线下结算 |

**v1 原则**：
- 平台只做**展示与撮合**，不抽成、不介入交易；
- 付费与免费交换在资料卡上通过「付费标签」区分（如「可付费带玩 ¥200/天」）；
- 后续（v2+）再考虑平台担保交易、抽佣或会员制。

### 5.4 信任机制（无认证，但有规则）

> 用户明确**不要认证概念**。替代方案：
- 资料卡公开、可被浏览；
- 平台规则 + 用户举报 + 黑名单；
- 社群内真实互动沉淀口碑（谁靠谱群里可见）；
- 建议用户线下见面在公共场所、报备行程（安全提示文案）。

## 6. 商业模式与演变路径

### 6.1 演变路径

| 阶段 | 形态 | 收入来源（未来） |
| --- | --- | --- |
| **V1（现在）** | 官网 + 社群 + 表单 + 资料卡 + 匹配 | 无收入，跑通闭环与流量 |
| **V2** | 私信 + 活动报名 + 付费服务撮合 | 服务撮合费 / 活动票务 |
| **V3** | AI 技能课程（线上/线下） | 课程收入 |
| **V4** | 本地体验产品 / 旅居套餐 | 体验产品分成 |
| **V5** | 企业游学 / 团建（To B） | B 端项目收入 |
| **V6** | 会员制社群 | 会员费 |

### 6.2 商业验证点（V1 阶段就要试探）

- 付费带玩是否有真实需求（表单里加「是否愿意付费带玩/被带玩」字段）；
- AI 教学是否有持续供给（深圳侧报名量）；
- 社区氛围能否自然组局（群内组局次数）。

## 9. 风险与对策

| 风险 | 对策 |
| --- | --- |
| 冷启动无流量 | 以深圳 AI/科技社群 + 云南旅居社群为种子渠道；小红书种草 |
| 双边失衡（都是想去云南的） | 云南侧先拉本地 KOL/民宿/新大理人，供给先行 |
| 安全与信任问题 | 平台规则、举报、黑名单、线下安全提示（无认证但有机制） |
| 免费交换变质为纯营销 | 强调交换对等原则，资料卡标注目的标签 |
| 品牌名未定影响传播 | 先用工作名，官网预留改名空间（文案集中可替换） |
