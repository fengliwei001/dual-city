# 02 · 产品需求文档（PRD）

> 产品工作名：**双城记** ｜ 版本：v0.1 ｜ 日期：2025-08-22 ｜ 状态：待评审
> 关联文档：[01-产品方案结构](./01-产品方案结构.md) ｜ [03-产品信息架构](./03-产品信息架构-IA.md)

---

## 1. 文档目的与范围

本 PRD 定义「双城记」V1 的产品功能需求，覆盖：

- 官网介绍页（品牌/玩法/三大场景/四城线路）
- 报名表单 + 社群入口
- 用户资料卡（公开名片 + 标签系统）
- 匹配系统（发需求 → 筛标签 → 推荐人）

**不在 V1 范围**（二期）：站内私信、活动报名页、付费服务交易闭环、后台运营系统。

---

## 2. 产品目标

1. 让「深圳教 AI × 云南带玩」的玩法被讲清楚、被看见；
2. 用**公开资料卡 + 标签**沉淀第一批用户资产；
3. 用**报名表单 + 微信群**把流量收进私域；
4. 用**匹配系统**证明「需求 → 人」的撮合逻辑成立。

北极星指标（V1）：**完成资料卡并加入社群的活跃交换意向用户数**。

---

## 3. 用户角色

| 角色 | 说明 |
| --- | --- |
| 深圳/杭州侧用户（教方） | 提供 AI 教学、资源对接、职业交流；想去云南被带玩 |
| 昆明/大理侧用户（带方） | 提供带玩、接站、吃喝、本地路线；想学 AI |
| 浏览访客 | 未报名，先看官网内容 |
| 运营者 | 管理员，维护线路内容、审核举报（V1 为人工操作） |

## 5. 功能详细需求

### F1 官网首页 / 介绍页（P0）

**目的**：3 秒讲清楚「这是什么、我能得到什么、怎么加入」。

**页面结构（从上到下）**：

1. **导航栏**（全局）：
   - Logo（双城记 · 工作名）
   - 一级菜单：**玩法**（下拉二级菜单 A/B/C）、**找人**、**四城线路**、**关于**
   - CTA：**加入我们**（按钮）
2. **Hero 区**：
   - 主标题：「深圳教 AI，云南带玩」/ 备选：「技能换风景，交换交朋友」
   - 副标题：让一线数字青年与云南在地生活者互相成为对方的本地朋友
   - 双 CTA：**先认识，进社群** / **发需求，找搭子**
   - 背景：深圳天际线 × 洱海/苍山融合视觉
3. **玩法三步区**（怎么玩）：
   - ① 填资料卡（你是谁、你会什么、你想换什么）
   - ② 找对人（按标签筛 / 发需求匹配）
   - ③ 组局（约线上教学 or 线下带玩）
4. **三大场景区**（卡片式，点击进入二级页）：
   - A. 深圳人想去云南有人带
   - B. 云南本地人想学 AI
   - C. 双方交朋友、建圈子
5. **交换形式区**：
   - 一对一互换 / 一对多 / 小团对小团 / 自由组局
   - 附加：支持付费带玩（带玩/陪游/摄影/包车，线下结算）
6. **四城联动区**：深圳 · 杭州 · 昆明 · 大理（四城卡片，点击进入线路页）
7. **标签云区**：展示核心标签（技能/爱好/交友目的）制造「人味」
8. **真实感区**（冷启动阶段用运营话术代替真实案例）：
   - 「首批 100 位双城玩家已就位」类文案 + 报名表单
9. **CTA 收口区**：报名表单（或跳转表单页）+ 微信群二维码 + 公众号/小红书关注
10. **页脚**：关于 / 规则 / 安全提示 / 联系方式

**验收标准**：
- 三大场景入口可点击进入对应二级页；
- 四城卡片可点击进入线路页；
- 双 CTA 均可达（社群入口 / 发需求）；
- 全页响应式可接受（PC 优先，移动端不破版）。

### F2 三大场景落地页（P0）

统一模板，三个页面共用一套框架，差异化内容按场景配置。

#### 页面模板结构

1. 场景 Hero（场景名 + 一句话价值主张 + 场景 CTA）
2. 「这是给谁看的」分侧描述（深圳侧看什么 / 云南侧看什么）
3. 典型交换玩法示例（2–3 个真实感场景卡片）
4. 对应标签入口（点击进入「找人」页并预筛标签）
5. 报名表单 / 社群入口
6. 常见问题（FAQ，4–6 条）

#### A. 深圳人想去云南有人带

- Hero 文案：「去云南，别一个人瞎逛」
- 价值：本地朋友带路、地道吃喝、私藏点位、有人接站
- 玩法示例：
  - 「我 11 月去大理旅居两周，找本地搭子带玩，我用 1 小时 AI 入门课交换」
  - 「深圳 4 人小团 × 大理 2 位本地带玩者，环洱海骑行 + AI 分享会」
- 标签预筛：常驻城市=深圳/杭州 × 擅长带你玩
- CTA：**发旅居需求** / **进群找搭子**

#### B. 云南本地人想学 AI

- Hero 文案：「在大理也能学 AI」
- 价值：一线 AI 从业者教、能落地到民宿/自媒体/接单场景
- 玩法示例：
  - 「1 小时 AI 入门课（小红书文案/智能回复/修图）」
  - 「一次资源对接：认识深圳 AI 圈的人」
- 标签预筛：常驻城市=昆明/大理 × 想学的 AI 内容
- CTA：**发学习需求** / **进群约课**

#### C. 双方交朋友、建圈子

- Hero 文案：「先交朋友，再谈交换」
- 价值：公开资料卡、按兴趣找人、进圈子组局
- 玩法示例：
  - 按标签找「摄影搭子」「咖啡搭子」「AI 学习搭子」
  - 加入城市圈：深圳圈 / 大理圈 / 昆明圈
- CTA：**浏览资料卡** / **进群交朋友**

### F3 报名表单 + 社群入口（P0）

**入口位置**：首页 CTA、三大场景页、导航按钮、页脚（多处可到达）。

**表单字段设计**（报名 = 轻量版，资料卡 = 完整版；报名表作为资料卡的前置采集）：

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| 昵称 | 文本 | 是 | |
| 城市 | 单选 | 是 | 深圳/杭州/昆明/大理/其他 |
| 角色 | 单选 | 是 | 想去云南被带玩 / 本地可带玩 / 都想 |
| 微信 | 文本 | 是 | 运营拉群用 |
| 想学/想换的 AI 内容 | 多选 | 否 | 走标签体系 |
| 擅长带你玩 | 多选 | 否 | 走标签体系 |
| 一句话介绍 | 文本 | 否 | 自由发挥 |
| 是否接受付费带玩服务 | 单选 | 否 | 是（线下结算）/ 否 / 看情况 |

**表单提交后行为**：
1. 成功页：显示「已收到，进群入口」→ 微信群二维码 + 公众号二维码；
2. 运营在后台（飞书表格/表单工具）收到记录 → 手动审核 → 拉群 / 邀请完善资料卡；
3. 提交数据可导出。

**社群入口（V1 流量承接）**：
- 微信群（核心）：按城市/角色分流（深圳群、云南群、四城总群）
- 微信公众号：内容沉淀（线路攻略、AI 教学文章）
- 小红书：种草引流（搜索「大理带玩」「深圳 AI」）
- 二维码物料：官网多处放置

### F4 用户资料卡（公开名片，P0）

> 用户明确要求：**公开名片**、**平台内可见**、**无认证概念**。

#### 4.1 资料卡字段（= 完整标签体系）

资料卡 = 公开名片，展示以下字段（即完整标签体系，用户可自定义补充）：

| 分类 | 字段 | 说明 |
| --- | --- | --- |
| 基础 | 性别 | 男 / 女 / 不愿透露 |
| | 年龄段 | 18–24 / 25–30 / 31–38 / 39+ |
| | 常驻城市 | 深圳/杭州/昆明/大理/其他 |
| | 当前所在地 | 常驻城市 ≠ 当前所在地（旅居中） |
| 能力 | 技能 | 可多选+自定义（AI 相关、摄影、设计、咖啡、手作…） |
| | 擅长带你玩的内容 | 私藏路线/美食/摄影点/徒步/骑行/咖啡馆… |
| | 想学的 AI 内容 | 入门/文案/图像/编程/数据分析/自媒体… |
| 交换 | 可交换时间 | 工作日晚上 / 周末 / 长假 / 旅居期间 |
| | 可交换形式 | 线上 / 线下 / 两者皆可 |
| | 是否愿意接待/带玩 | 是 / 否 |
| | 是否愿意教学 | 是 / 否 |
| 社交 | 交友目的 | 旅行搭子 / 学习搭子 / 资源合作 / 纯交朋友（可多选） |
| | 一句话介绍 | 自由文本（展示在卡片上） |

#### 4.2 标签体系定义

**原则**：预设标签 + 用户自定义标签；标签可被搜索与筛选。

**预设标签字典**（V1 内置）：

- **性别**：男 / 女 / 不愿透露
- **年龄段**：18–24 / 25–30 / 31–38 / 39+
- **常驻城市**：深圳 / 杭州 / 昆明 / 大理 / 其他（可多选）
- **当前所在地**：同上
- **技能**：AI 工具应用 / AI 编程 / 产品设计 / 摄影摄像 / 文案写作 / 咖啡手冲 / 手作 / 户外徒步 / 其他（自定义）
- **爱好**：徒步 / 骑行 / 探店 / 咖啡 / 音乐 / 露营 / 摄影 / 读书 / 桌游 / 其他（自定义）
- **擅长带你玩**：私藏路线 / 地道美食 / 拍照点位 / 环湖骑行 / 古镇漫步 / 咖啡馆巡礼 / 接站带路 / 其他（自定义）
- **想学的 AI 内容**：AI 入门 / AI 文案 / AI 图像 / AI 编程 / 数据分析 / 自媒体运营 / 智能体搭建 / 其他（自定义）
- **可交换时间**：工作日晚上 / 周末 / 节假日 / 长假旅居 / 随时
- **可交换形式**：线上 / 线下 / 线上+线下
- **是否愿意接待/带玩**：愿意 / 暂不
- **是否愿意教学**：愿意 / 暂不
- **交友目的**：旅行搭子 / 学习搭子 / 资源合作 / 纯交朋友

#### 4.3 资料卡展示样式（公开名片）

```
+------------------------------------------------------+
|  [头像]  昵称 · 25-30 · 深圳                          |
|          「在南山写代码，想去大理晒太阳」               |
|  技能：AI 工具应用 · 摄影                              |
|  爱好：骑行 · 咖啡 · 露营                              |
|  可换：教 1h AI 入门 | 周末可线上                      |
|  交友目的：旅行搭子 · 学习搭子                        |
|          [约局] [进群认识]                            |
+------------------------------------------------------+
```

**卡片信息密度要求**：一眼看到「谁、在哪、会什么、想换什么」。

### F5 匹配系统（P0）

> 目标：**发需求 → 筛标签 → 推荐人**。V1 为轻量匹配（标签规则匹配 + 列表展示），不做算法。

#### 5.1 发需求（需求单）

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| 我要 | 单选 | 找带玩 / 找 AI 教学 / 找搭子 |
| 我在 | 单选 | 深圳 / 杭州 / 昆明 / 大理 / 其他 |
| 想找的人 | 标签多选 | 城市 / 技能 / 爱好 / 交友目的（复用标签体系） |
| 时间 | 单选 | 近期 / 本周末 / 下月 / 旅居期间 |
| 形式 | 单选 | 线上 / 线下 / 均可 |
| 我能提供（交换） | 文本/标签 | 教 AI / 资源对接 / 带玩 / 其他 |
| 一句话需求 | 文本 | 自由描述 |
| 联系方式 | 文本 | 微信（可选，公开或进群获取） |

**提交后**：需求进入「需求墙」（公开展示，含发布时间）。

#### 5.2 找人/筛选（浏览资料卡）

- 筛选项（侧栏/顶栏）：常驻城市、角色（带玩/教学）、技能、爱好、交友目的、可交换形式、年龄段
- 列表：资料卡网格/列表展示
- 空态：提示「暂无完全匹配，先进群认识人」

#### 5.3 推荐逻辑（V1 规则匹配）

推荐优先级（可配置权重）：
1. **城市匹配**：常驻城市 = 需求中的目标城市（最高优先）
2. **标签匹配**：技能/爱好/交友目的与需求标签重合数
3. **可交换时间/形式匹配**：可线上优先匹配可线上
4. **互惠匹配**：我的「我能给」= 对方「想学的/想要的」（推荐标签提示「他想要你会的」）

#### 5.4 约局（轻量）

- 资料卡 / 匹配结果上提供 **「约局」按钮**：
  - 提交约局意向（时间/形式/说明）→ 生成一条约局记录 → 运营在群内撮合 or 交换联系方式
- V1 不做站内私信（二期），约局意向通过**表单/群内人工撮合**完成闭环

## 9. 验收标准（总）

1. 用户从官网 3 步内能完成「提交报名并看到进群二维码」；
2. 用户可创建公开资料卡，选择全部 13 类标签并支持自定义补充；
3. 用户可发需求，并按城市/技能/爱好/交友目的筛选出推荐人列表；
4. 三大场景页均可从首页一级菜单进入，且各有独立 CTA；
5. 四城线路页展示四城景点 + 线路，并有「发需求」收口；
6. 全站文案中品牌名集中可替换（为正式改名留余地）。
